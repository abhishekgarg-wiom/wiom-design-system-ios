# Colour usage: roles, pairings and source boundaries

This reference explains existing iOS rules. It defines no new colour, token, product behaviour or owner ruling. Exact values and primitive mappings live in [tokens.md](tokens.md); component-specific state tables and `../../IOS_DECISIONS.md` take precedence. The canonical HTML is a view of these skill files, not a second source of truth.

## 1. Primitive versus semantic colour

| Layer | Purpose | Use in implementation |
|---|---|---|
| Primitive, such as `Neutral/700` or `Brand/600` | The internal palette value | Internal design-system implementation only. Never choose a primitive directly in feature code. |
| Semantic token, such as `text/subtle` or `bg/brand` | The role of the colour on a specific element | Feature code uses the semantic Swift accessor generated by the contract. |
| Component state | The combination for a component, variant and state | Follow the component's table. Do not infer a state from the token name alone. |

Several semantic tokens can map to the same primitive. That does not make their roles interchangeable. A primitive with no semantic alias is still an internal palette entry, not permission to create a new role. Missing palette steps are undefined; do not interpolate them into the design system.

RGB and HSL equivalents shown in a reference UI are calculated representations of the documented hex. They are not additional tokens. A list of component documents referencing a token is a discovery aid, not proof that every reference is a resting-state usage.

## 2. Element-first namespaces

| Namespace | Element | Correct API role | Avoid |
|---|---|---|---|
| `bg/*` | Background or filled shape | SwiftUI background / shape fill | A background token used as a text or icon tint |
| `text/*` | Text | Text foreground | Using an icon tint because it looks like the same colour |
| `icon/*` | Material Rounded template glyph | Image foreground | Using text colour tokens for a glyph |
| `stroke/*` colours | Border or divider | Stroke / strokeBorder | Confusing a colour with the separate border-width collection |
| `chat/*` | Documented chat roles | Bubble, canvas or reply accent | Replacing the whole app's neutral background family |
| `overlay/scrim` | A modal backdrop | The existing scrim colour at its specified alpha | Creating a new black opacity per screen |

## 3. Existing role combinations

These are a lookup index into the component rules, not independent recipes that override them.

| Use case | Fill / surface | Text | Glyph / stroke | State or caveat |
|---|---|---|---|---|
| Default light screen | `bg/default` | `text/default`; secondary role `text/subtle` | Action `icon/action`; decoration `icon/nonAction` | Surface owns gutters and safe areas. |
| Dark or premium header | `bg/inverse` or `bg/brand/bold` | `text/inverse` only | `icon/inverse` | Never use `text/brand` or `text/subtle` on these surfaces. |
| Primary CTA | `bg/brand` | `text/onBrand` | `icon/inverse` | Pressed fill `bg/brand/pressed`. |
| Secondary / Tertiary CTA | Transparent at rest | `text/brand` | `icon/brand`; Secondary border `stroke/brand/focus` | Pressed fill `bg/brand/subtle`; the known pressed contrast exception remains recorded. |
| Destructive CTA | `bg/critical` | `text/onCritical` | `icon/inverse` | Pressed fill `bg/critical/pressed`; always an escape action. |
| Pre-booking CTA | `bg/brand/accent` | `text/onBrandAccent` | `icon/action` | Pressed fill `bg/brand/accent/pressed`; do not use a white label. |
| Disabled filled CTA | `bg/disabled` | `text/disabled` | `icon/disabled` | Token swap, not blanket opacity. Secondary/Tertiary retain their component-specific transparent treatment. |
| Input at rest | `bg/default` | Value `text/default`; placeholder `text/disabled` | `stroke/subtle`; leading `icon/nonAction` | Border width `stroke/small`; label ramp is defined by the input skill. |
| Input being edited | `bg/default` | `text/default` | `stroke/brand/focus` | Border width `stroke/medium`; this editing state is not an iPhone keyboard focus ring. |
| Input error | `bg/default` | Helper `text/critical` | `stroke/critical/focus`, `icon/critical` | Error must also be explained and announced. |
| Input Warning | `bg/default` | Helper `text/onWarning` | `stroke/warning`; `icon/action` on `bg/warning/subtle` | D31 requires a dark glyph on the warning-tinted icon container; whole input stays neutral. Container: Icon Badge Sm (D35). Border contrast remains open. |
| Read-only input | `bg/subtle` | `text/default` | `stroke/subtle` | Readable and selectable; not Disabled. |
| Pressed list row | `bg/subtle` | Existing row text roles | Existing row glyph roles | Instant pressed state. Selected wins when both states could apply. |
| Selected row / chip | `bg/selected` | Component-defined selected text | Chip border `stroke/selected` | Rows and chips fade selection in/out with `Wiom.Motion.microStandard` (D28); a row’s radio/checkbox fades with its background. Pressed row fill remains instant. Do not copy the chip's label role into every selected row. |
| Neutral icon badge | `bg/subtle` | No text inside | `icon/nonAction` | Decorative; parent owns meaning. |
| Dialog Alert header | `bg/subtle`, 48 pt circle | Dialog title/body use their own roles | `icon/action` | Owner lock `23f67f9` overrides the generic Neutral badge tint. |
| Status icon badge | Matching `bg/{tone}/subtle` | Meaning on the host | Matching `icon/{tone}` | Warning is the D31 exception to same-family naming: dark icon/action on subtle or solid Warning background. Gold icon/warning is ratings-only. |
| Toast, all four types | `bg/default` | `text/default`, except Warning `text/onWarning` | `icon/action` for Warning (D31); other types retain their status family | Owner lock: neutral fill for all types. D31 uses dark `icon/action` on `bg/warning/subtle` for the toast Warning glyph, measured 10.85:1, in an Icon Badge Sm (24 pt circle, 16 pt glyph; D35). Action text is always `text/brand`. |
| Progress tone | `bg/muted` track; `bg/info`, `bg/brand` or `bg/positive` fill | The component's value / title / pill roles | Stage glyph roles from progress skill | Shared ladder; no warning/critical progress fill. |
| Skeleton | `bg/muted` placeholder | No fake content text | Shimmer band as defined by loader | Static with Reduce Motion. |
| Modal scrim | `overlay/scrim` | Not a text surface recipe | No radius or shadow on scrim | Full-screen backdrop; the dialog or sheet owns its own elevation. |
| User chat bubble | `chat/bg/userBubble` | Existing chat text role | Optional documented accents | Supplied chat rules own the content and form. |
| Chat canvas / system bubble | `chat/bg/canvas` / `chat/bg/systemBubble` | Existing chat text role | `chat/stroke/replyAccent` for reply preview | These roles do not introduce another app theme. |

## 4. Contrast is role-specific

Use the complete contrast table in [tokens.md](tokens.md). Text, meaningful graphics and disabled states are not interchangeable tests. Never communicate a status through colour alone: include words, a state value or another documented cue.

D31 closes the Warning colour contradiction: gold is ratings-only; every Warning indicator uses dark icon/action on subtle or solid Warning background. The whole toast/input stays neutral. Other documented contrast questions remain open; do not change their colours without an owner ruling.

## 5. Light appearance and unavailable values

The app is light-only. A dark brand header is a component surface, not support for an app-wide dark theme. Hover tokens, Figma-only unused surfaces, stale paint styles and the legacy blue/orange ramps are not active iOS roles. See `tokens.md` section 10.

If no semantic token fits, report the gap. Do not publish an invented token or a nearest-colour substitution. The switch thumb uses `icon/inverse` (D34). Documentation may show the recorded appearance while marking that implementation gap explicitly.

## 6. Component authority

For exact variants, states, pairing, anatomy and behaviour, read the relevant component skill. This index does not supersede the CTA state tables, the input label ramp, the row typography owner lock, the toast's decided 8 pt vertical clearance (D29) or the unused status of bottom navigation.


## 7. Final Warning combinations

Use [warning-combinations.md](warning-combinations.md) for the three approved combinations. D31 applies across toast, input, icon badge and other Warning indicators. Gold-on-yellow is not an accepted Warning exception.
